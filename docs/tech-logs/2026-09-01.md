## 本轮目标与基线判断

仓库从 GitHub 克隆到 `D:\AI\Codex\Zaqizaba\shuati platform`。原实现已经有注册、题库、前端编辑器和本地判题纵向链路，但运行态使用内存仓储，重启会丢失账号、题目和提交；`LocalCppRunner` 直接在宿主机运行不可信代码，不能暴露公网；项目也没有 HTTPS、免费域名或服务托管配置。

“能线上做题”的最低安全边界应同时包含：业务状态可恢复、用户代码不在宿主机直接执行、后端只监听回环地址并由反向代理提供 HTTPS。只把原端口映射到公网不算完成。

## 可复用实现判断

个人和小规模试用先使用原子状态文件，而不是在本轮仓促接入半套 MySQL。`users.state`、`problems.state`、`submissions.state` 位于 `storage.state_dir`，写入时先生成 `.tmp` 再替换正式文件。字段中的任意 UTF-8 文本使用十六进制编码，避免换行、制表符和引号破坏行协议。该方案只适用于单进程、单机实例；多实例扩容必须迁移到数据库。

公网配置强制 `app.environment: production` 与 `judge.runner: docker` 组合，并拒绝默认或占位管理员密码。Docker runner 使用固定命令模板，不拼接用户源码到 shell，容器设置 `--network none`、CPU/内存/pids 限制、只读根文件系统、临时 `/tmp`、`no-new-privileges`、删除 capabilities，并用 `RLIMIT_FSIZE` 限制输出文件。宿主进程仅挂载当前提交的临时目录。

同步 HTTP 判题仍使用“创建后按指定 submission id 领取”，不能调用通用 `claimNextPending`。后者在并发或恢复队列存在旧任务时可能领取别人的提交，导致当前提交被错误完成而旧任务停在 Running。本轮新增 `claimPendingById` 并以回归测试覆盖。

免费域名选用 DuckDNS 子域名，HTTPS 使用 Nginx + Certbot。部署入口是 `deploy/install_ubuntu.sh`，生产配置在 `/etc/shuati/app.yaml`，业务状态在 `/var/lib/shuati`，日志在 `/var/log/shuati`，服务单元是 `deploy/shuati.service`。部署脚本需要公网 Ubuntu 主机、DuckDNS 名称/token 和管理员密码；这些外部资源不能写进仓库。
